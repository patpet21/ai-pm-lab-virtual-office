## Non collaudato / non disponibile

- Lettura autenticata del Master Leads: manca un file di credenziali Google locale già autorizzato. Non è dichiarata una sincronizzazione riuscita e non esiste una funzione di scrittura.
- Riuso del connettore Google già autorizzato nella chat/app Codex: provati i metodi ufficiali `mcpServerStatus/list` e `app/list` in un processo dedicato. Entrambi hanno raggiunto il timeout di 30 secondi. Non si deduce indisponibilità permanente e non si dichiara un collegamento backend riuscito. Nessun account, progetto Cloud, login o token nuovo è stato creato; alternative con il proprio account documentate.
- Deploy nell’account Netlify e collegamento da una sua origine HTTPS: non effettuati. La configurazione è pronta sul branch; restano da verificare impostazioni effettive del sito e autorizzazioni di rete locale del browser.
- Esecuzione completa delle tre skill, relativa pipeline e sottofasi commerciali: volutamente non avviate durante lo sviluppo. La lettura di SKILL.md non viene dichiarata completamento di una skill.
- Approvazione effettiva di una modifica file, domande `requestUserInput` e altri tipi di strumenti: il relativo codice o la visualizzazione dei payload è presente, ma i controlli live hanno esercitato chat, shell di lettura e approvazione comandi con **rifiuto**. Non è stata eseguita una scrittura per dimostrare un’approvazione.
- Controllo di chat Codex desktop già in esecuzione, sottagenti autonomi e collegamenti Internet ad App Server: non implementati. La superficie supportata comprende le sessioni create dal bridge locale.

## Suite originale server non verde su Windows

`npm test` ha dato: frontend 195 passati; server originale **650 passati, 50 falliti, 25 saltati** su 38 file (31 passati, 6 falliti, 1 saltato). I file sorgente/test di `server/`, `core/` e `adapters/` non sono stati modificati, verificato con `git diff --exit-code -- server core adapters`.

Le aree in errore comprendono configPersistence, directories, clientMessageHandler, consentFlow, mockClaudeRunner e server. Dai messaggi e dal codice dei test emergono assunzioni sull’isolamento tramite HOME, percorsi e permessi POSIX, timeout dei processi di test e un ECONNRESET. Non è stata eseguita una seconda baseline separata: questi esiti non sono presentati come regressioni risolte né come suite interamente passata. Il bridge Codex usa un servizio separato e le sue prove reali sono passate.

`npm ci` ha inoltre segnalato 12 vulnerabilità nell’albero di dipendenze ereditato (2 moderate, 9 alte, 1 critica). Non sono state cambiate dipendenze o applicate correzioni automatiche non verificate. Il nuovo bridge a runtime usa moduli nativi Node; il vecchio server Fastify non viene avviato da `npm run office`. Rimane necessario un audit dedicato prima di qualificare l’intero repository per produzione.

Vite segnala un bundle frontend superiore a 500 kB; la build riesce. Il protocollo Codex App Server rimane sperimentale secondo la documentazione ufficiale.
